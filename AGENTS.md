# AutoCut development guide

The current exporter lives in `studio/`. Read `studio/AGENTS.md`, `studio/CLOUD_SETUP.md` and `studio/UPSTREAM.md` before making changes.

The root Python application is a historical audited prototype. Its Streamlit path contains simulated results and other processing paths have known correctness defects. Do not describe it as a verified product. Preserve historical source and changes; implement current product work in `studio/`.

The project has three tracks: a reliable university project demonstration, a publishable study, and a technically justified invention patent application. Everyday direct export is the current product priority; lecture/interview editing is additional planned work. Everyday samples are not lecture evaluation data. Private research plans are maintained locally and are not required to run the public exporter.

Production outputs must use real inputs and provider responses. Never label mock data, template transcripts or unedited source videos as successful editing. Required failures must stop; optional failures require explicit degradation. Record success, degradation and failure, actual providers, errors, output validation and available usage measurements. Preserve failed runs. Engineering test fixtures must remain explicitly marked and excluded from research evidence.

Keep credentials, personal media, runtime records, resources and unpublished patent candidate details out of Git. Keep upstream licenses and attribution. Push only when authorized. Use conventional commit messages for logical changes and test the relevant contracts and real media output. Never fabricate author identities or empirical claims.
