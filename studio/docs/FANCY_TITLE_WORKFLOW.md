# 可复用花字制作流程 v1

更新：2026-10-06。面向8GB Mac和日常短视频；本轮已接入产品并导出真实拉面游戏视频。

## 1. 当前成果

| 样式 | 字体 | 视觉构成 | 适用时刻 |
|---|---|---|---|
| 橙黄冲击 `comic_pop` | 得意黑 | 奶黄到橙色渐变、深紫内描边、白外描边、偏移阴影、星芒 | 开场、动作高潮、提醒 |
| 薄荷贴纸 `mint_sticker` | 荆南麦圆 | 浅薄荷渐变、深绿描边、白外沿、硬阴影、轻微倾斜 | 欢乐互动、可爱反应、日常记录 |
| 漫画强调 `pink_punch` | 得意黑 | 奶白到粉色渐变、紫色描边与阴影、星芒、轻微倾斜 | 惊喜、笑点、结尾 |

三种样式都使用可替换的文字，整体弹入后停留，末尾淡出。装饰是本机绘制的原创几何图形。当前实现的是**整体花字动画**；尚未实现逐字跳动、自动卡音乐鼓点、情绪触发、自动人物避让或复杂粒子。

语音字幕保持下方白字。花字表达主题或编辑提示，不应把推测的台词包装成现场原话。

## 2. 网上检索与选材结果

采用发布者/获授权发布仓库的字体，保存固定版本、许可和哈希：

- [得意黑官方仓库](https://github.com/atelier-anchor/smiley-sans)：发布者建议用于视频标题和字幕，SIL OFL 1.1。选定官方release **v2.0.1** 的TTF，2,629,764字节。
- [荆南麦圆发布仓库](https://github.com/maoken-fonts/KNMaiyuan)：仓库说明其获字坊授权转发，介绍圆润手写风格，SIL OFL 1.1。固定提交 **580b2bb873828122f7816f1c5c4caf2667cba62f**，TTF 7,996,068字节。
- 现有语音字幕继续使用Noto CJK；不修改字体文件。字体许可与版权声明随资源保存，新增样式模板只修改排版和图形效果。

本轮没有采用来源或授权不明的下载站花字包。生图并非本轮实际使用的环节：本机字体绘制已能提供清楚、可换文案、带透明通道的花字。检索到的字体与自己绘制的效果共同组成模板。

## 3. 标准生产流程

### 第一步：决定花字要强调什么

先写一张花字清单：`文字 / 对应镜头或事件 / 起止时刻 / 样式 / 位置`。

- 每条优先4—10个汉字；只表达一个意思，例如“千万别拉断”。
- 开场、动作转折、反应和收尾优先；不要逐句把所有语音变成大花字。
- 20秒视频初步建议3—5个重点，最终按实际节奏检查。这是编辑建议，不是经过研究验证的最优频率。现有拉面验证样片沿用了上一版的7条标题，以直接比较外观。
- 表情/心理判断要有依据；没有听清的台词交给字幕核对，不能从主题猜台词。

### 第二步：确认字体和装饰来源

只采用能核对到实际授权的字体/素材。下载后保存原始链接、固定版本、作者/权利人信息、许可和SHA-256。新增第三方图形也要进入来源清单；不能把“网上能下载”当作可复用依据。

本轮两个字体已由 `scripts/bootstrap_fancy_fonts.py` 固定校验。字体共约10.1MiB；不涉及神经网络模型。资源留在 `resource/fonts/fancy/`，运行记录只保存公开的字体身份与哈希。

### 第三步：先做静态模板

用字体绘制清楚的正文，再依次加入填色、内描边、外描边、偏移阴影和少量装饰。每个模板最多保留2种主色加中性描边；装饰不应抢过字。

本轮基准尺寸为404×720。字高约画面高度6.4%，字号同时按画面宽度限制；横屏同样按实际尺寸计算。宽度超过限制则缩小/换行，最多两行，不能靠裁掉文字解决。

模板参数集中于 `src/open_storyline/utils/fancy_titles.py` 的 `STYLES`；字体身份在 `FONTS`。不要为每条文案单独写特效代码。缺字、字体损坏、未知样式均明确失败，不生成方框或悄悄替换字体。

### 第四步：输出透明素材

以RGBA PNG导出，周围留透明边距，保留原文字和模板参数。普通RGB图不能直接作为透明贴片使用。

运行：

```bash
PYTHONPATH=src:. .venv/bin/python scripts/preview_title_styles.py
```

产物在 `runtime-local/verification/fancy-titles/`：

- 9张透明PNG：3种样式 × 3条示例文字。
- `style-sheet.png`：三种样式的对照图。
- `manifest.json`：文字、尺寸、样式、字体身份、参数、资源哈希与装饰来源。
- `fancy-title-pack.zip`：上述示例素材和字体许可。PNG用于贴片，任意新文案应从模板重新绘制；ZIP不含字体二进制，字体可由安装脚本重新取得。

### 第五步：定义短促、可读的动画

本轮整体弹入约240ms，比例依次为：

`0.74 → 0.89 → 1.02 → 1.10 → 1.07 → 1.03 → 1.01 → 1.00`

停留后在最后140ms淡出。正常阶段不持续晃动。建议显示约1.2—2秒，具体按字数和镜头调整；当前样片标题沿用原来最多2秒的时间窗。

实现缓存8个小画布入场帧，动态透明度用于退场；没有预先生成整段全尺寸视频帧，也不加载大模型。字幕实际显示的起止时刻继续取成片时间线。

### 第六步：叠到真实视频上检查

- 花字画布锚点位于画面上方约5.5%；透明内边距决定实际字面位置。
- 静态素材宽度保留最大1.10倍弹入空间；动画画布控制在画面宽度90%以内。
- 语音字幕放在底部安全位置，花字与语音分别渲染。
- 亮背景、暗背景都要检查对比度；至少看入场、最大放大、停留、退场四类帧。
- 逐个镜头确认没有压住人脸、手部关键动作、已有画面文字。**当前位置是固定上方，人物避让依赖检查，并非自动完成。**

如果挡住内容，先缩小、移位或取消这一处花字，再考虑更复杂的自动避让算法。

### 第七步：导出并记录

新任务在页面选择“标题 / 花字样式”。已有成片在“换一种花字”里选择，点击重新导出；不需要再次填Key或重新识别。

每次生成独立run_id，保留父运行。记录样式ID、版本、字体SHA-256、制作方式、修改的标题数量、输出尺寸/时长/音轨/完整解码结果。模型调用用量和渲染费用分开描述：本次未重新调用模型，但没有对电费或机器总成本作测量。

语音SRT不携带花字样式；最终MP4烧录花字。文字清单、样式和时间线应同时保留，不能只保存最终视频。

### 第八步：验收后收为模板

最小验收条件：

1. 所用汉字都有真实字形，没有缺字方框；透明PNG四边完整。
2. 最大放大时不出边，停留时清楚，退场后遮罩为0。
3. 花字没有覆盖关键人物/动作，普通语音字幕仍可读。
4. 换样式不改变原视频切点、语音文字和SRT时刻。
5. 成片时长、音轨和完整解码通过，浏览器能正常显示。
6. 原始版本和新版本均保留，资源来源与样式可追溯。

合格后锁定模板版本；新增模板重复静态样张、动画边界与真实视频检查。未来可按场景增加“震惊”“疑问”“成就”等模板，不必每次重新设计。

## 4. 如果以后需要生图装饰

此分支尚未实测。仅用于难以用几何图形或已授权素材表达的装饰，例如透明卡通面条/庆祝贴纸。

建议先生成**无文字、独立、透明背景**的装饰，再用本地真实字体叠字。保留生成提示、模型/来源、原图、透明边界检查和版本；先人工检查再加入素材库。每次改文案复用装饰。不能把“原始生成图”描述成已经通过质量或许可核验的素材。

若以后需要与其它字幕编辑器交换效果，可研究ASS的描边、阴影、缩放、移动、淡入淡出；语法见[Aegisub官方文档](https://aegisub.org/docs/latest/ass_tags/)。当前产品采用Pillow + MoviePy，尚未实现ASS效果导入导出。

- 成片运行：`db884a98-f497-4051-92c4-bc4ba67882df`；父运行 `a226272e-d852-4be9-991f-7c5c93b37889` 保留。

- 切点时间线和父运行逐项一致；语音SRT与父运行逐字节一致。音频重新编码，未宣称音轨字节一致。
- 实际导出0.04、0.12、0.32、1.98秒画面检查入场、停留、退场，透明背景与中文正常。第一镜头的人脸没有被花字遮挡；不能外推为任意视频自动避让。
- 页面真实操作换样式并导出，播放器实际报告20秒、readyState=4、无媒体错误；截图保存在 `ui-final.png`。
- 21项工程测试通过：其中三样式的动画边界/透明遮罩、缺字失败，以及HTTP换样式→实际渲染→父记录不变→SRT不变。两个其他样式已生成静态样张并做动画帧检查，尚未分别导出20秒用户视频。
- 本轮未新增云端API或生图调用；不把花字外观改进视为论文效果或算法创新的证据。

源码与可复用制作流程随当前版本发布；实际用户视频、运行记录与字体二进制保留在本地。
